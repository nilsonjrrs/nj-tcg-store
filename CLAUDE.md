# NJ TCG Store — Site Vitrine

Site vitrine da NJ TCG Store (Pokémon TCG, Curitiba). O cliente monta o pedido e finaliza pelo WhatsApp.

## Regras do projeto (não mudar sem combinar)

- Site estático: HTML, CSS e JS puros. **Sem build, sem framework, sem dependências.**
- **Sem checkout e sem pagamento online.** O fechamento do pedido é sempre via link do WhatsApp.
- Fonte da interface sempre **Arial**. Desde o redesign de 21/11/2026 os **títulos** usam Big Shoulders Display (arquivo local em `fonts/`, sem CDN) — ver "Redesign da loja" no fim deste arquivo; se o Nilson não aprovar, basta trocar `--font-display` em `css/loja.css`.
- Cores sempre **roxo e laranja** (design tokens em `css/style.css`: `--color-bg`, `--color-surface`, `--color-primary` (laranja), `--color-accent` (roxo), `--color-ink`). Botões com fundo colorido usam texto escuro (`--color-ink`), não branco — é o que garante contraste AA; não voltar pra texto branco nesses botões. Desde 22/11/2026 o site tem **dois temas** (escuro, o original, e claro — botão de sol/lua no cabeçalho, ver "Feito"): qualquer cor nova de superfície/texto tem que ser um token com valor pensado pros dois `:root` (padrão e `[data-theme="light"]`) em `css/style.css`, nunca uma cor fixa que só funciona num dos dois.
- **Toda vez que `css/style.css` ou `css/loja.css` mudar, subir o `?v=...` dos dois `<link>` em `index.html` no mesmo commit** — sem isso o GitHub Pages/navegador serve o CSS antigo cacheado na mesma URL e a mudança parece não ter saído (já aconteceu 2x).
- WhatsApp e as opções de entrega/pagamento ficam centralizadas em `js/config.js`.
- Produtos ficam centralizados em `js/produtos.js` (schema: sku, nome, categoria, colecao, idioma, preco, precoPix, estoque, frase (opcional), img). `preco` é o preço no cartão; `precoPix`, quando presente, é o preço no Pix (menor) — aparece em destaque no card/detalhe e é o valor usado no carrinho/mensagem do WhatsApp quando o cliente escolhe Pix (`Catalogo.precoParaPagamento`, usado em `js/pedido.js`).
- JS dividido em módulos por responsabilidade (`tilt.js`, `carrinho.js`, `zoom.js`, `catalogo.js`, `pedido.js`, `app.js`) — não virar um arquivo único de novo.
- Nunca expor custo/margem/fórmula de precificação no código do front-end (fica só em planilha/script privado — ver skill `tcg-pricing-margin`).
- Nunca inventar prova social (depoimento, avaliação, "estoque esgotando") que não seja real.
